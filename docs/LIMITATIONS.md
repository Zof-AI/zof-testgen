# Scope and limitations

TypeScript support selects named exported top-level synchronous function declarations with bodies. Python support selects top-level synchronous function definitions. Class methods, TypeScript arrow functions, async functions and generators are outside the supported initial scope. Functions must be explicitly selected; the tool does not decide which Git changes matter.

Without a supplied expected result there is no test oracle: generated TypeScript tests are TODO and Python tests are skipped. Boundary and invalid-input suggestions are advisory prose. Covered-branch IDs are caller-supplied hints, never measured coverage or proof that a branch is tested. TypeScript validation checks syntax, not whole-project types, imports or runtime compatibility. Python parsing does not execute imports, decorators or module statements.

Generated tests do execute the selected module when a user later accepts and runs them. Review that module, imports and fixtures first and use an isolated execution environment for untrusted code. No generated test is automatically run, guaranteed to catch every defect or labeled verified. Source transmission is limited to explicit local-model requests. The automated synthetic acceptance proves only the supplied known clamp bug is detected and its correction passes in both supported languages.

Output paths are fixed under generated/. Do not concurrently replace workspace directories while generation or writes are in progress. The optional Ollama adapter uses one explicit loopback request after consent. It requires a trusted server configured for local-only inference; a network client cannot prove the server does not forward data. Cloud-tagged models, custom URLs, authentication, redirects and model downloads are unsupported. No real language-model quality or live acceptance is verified. Hosted Zof integration is unimplemented and no Zof endpoint is assumed.

Model generation sends selected function declarations without unrelated imports or supporting functions, so the model may lack context. Token and source limits may also reduce context. Model-generated oracles can be incorrect even with valid syntax. Known secret/URL patterns in generated code cause rejection rather than silent rewriting; this detector is not a guarantee of exhaustive secret detection.

Recognized sensitive values in reproductions and generation metadata also cause rejection before candidate creation, and selected source is checked before a model request. Sensitive key patterns are conservative: use synthetic data, but be aware that benign values under keys such as password or token can still be rejected. Original oracle values are never modified to make a request pass.
